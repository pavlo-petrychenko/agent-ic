# Contributing

## Setup

1. Install Docker Desktop (or OrbStack) and [mise](https://mise.jdx.dev). `README.md` has the exact steps. On Windows, see "Windows" in `README.md`: native with `tools\windows\setup.ps1`, or inside WSL2.
2. Run the one-time setup:

```sh
mise run setup
```

It installs the pinned tools, creates `.env` and a local certificate, adds the local hosts, builds the dev image, starts the stack, installs dependencies and the git hooks on the host, and runs migrations and seed.

Run pnpm scripts through mise (`mise exec -- pnpm <script>`) or activate mise in your shell. The tasks and scripts are listed in [AGENTS.md](AGENTS.md).

## Branches and pull requests

- Branch as `<type>/<short-description>`: `feat/auth-sessions`, `fix/refresh-reuse`.
- Pull request titles are conventional commits: `feat(identity): add refresh rotation`. Squash merge only, so the title becomes the commit message and release-please builds the changelog from it.
- Keep pull requests under about 600 changed lines, not counting generated files and lockfiles. Split bigger work into stacked pull requests.
- Fill in the pull request template. Never commit secrets.
- A pull request that changes UI carries screenshots of every changed story or screen. Commit the images to the `pr-assets` branch and embed them in the description by their raw URL, so they never enter the history of the working branch.
- Migrations are generated by drizzle-kit, committed, and never edited after merge. A breaking change goes expand, deploy, contract.

Full rules: [docs/rules/git.md](docs/rules/git.md).

## How to review

- Read the description first, then the tests, then the code.
- Tests are optional during the MVP. When a pull request has tests, check that they describe behaviour and that a bug-fix test fails without the fix.
- Check layer and module boundaries even when `depcruise` is green: a use case should read as a short sequence of calls, with logic in services.
- Check that migrations are expand-only, or that the pull request says it is the contract step.
- Check the pull request title is a conventional commit.
- Ask for a split when the diff is too big to review in one sitting.
- One approval is required on `main`. The repo admin may merge without one.

## How deploys work

- Every merge to `main` runs CI, builds the images and the Helm chart, scans the images with Trivy, and publishes all three to GHCR with the same version (`X.Y.Z-main.<run number>`).
- A version bump in the `agent-ic-deploy` repository pins that version for an environment, and Argo CD syncs it.
- release-please opens a release pull request that collects the changelog and version.
- A freeze switch stops auto-deploys before a demo.
- What changes with the code lives in this repository. What changes with the environment (values, versions, add-ons) lives in `agent-ic-deploy`.
