# Git and pull requests

- **Branches:** `<type>/<short-description>` (`feat/auth-sessions`, `fix/refresh-reuse`).
- **Pull request titles** follow conventional commits (`feat(identity): add refresh rotation`). Squash merge only, so the title becomes the commit message and release-please builds the changelog from it. No CI check; reviewers keep it.
- **Small pull requests:** aim under about 600 changed lines, not counting generated files and lockfiles. Bigger work is split into stacked pull requests.
- **`main` is protected for the team:**
  - CI must be green;
  - 1 approval;
  - no direct pushes;
  - linear history;
  - the repo admin bypasses the rules: pushes directly and merges without an approval.
- **Pull request checklist** (also in `.github/pull_request_template.md`):
  - tests added;
  - migrations are expand-only, or marked as the contract step;
  - docs and decisions updated;
  - screenshots for UI changes;
  - no secrets.
- **Migrations:** generated by drizzle-kit, committed, never edited after merge. A breaking change goes expand, deploy, contract.
- **Releases:** every merge to `main` deploys. release-please opens the release pull request. The freeze switch stops auto-deploys before a demo.
